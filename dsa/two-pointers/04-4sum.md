# 04. 4Sum

- **Difficulty:** Medium
- **Pattern:** Two Pointers
- **Asked at:** Amazon, Microsoft, Google, Bloomberg

## Problem
Given an integer array `nums` and an integer `target`, return all unique quadruplets `[a, b, c, d]` whose sum is `target`. A quadruplet cannot reuse an element.

**Input**
- `nums`: a list of integers.
- `target`: the required sum.

**Output**
- A list of unique quadruplets. **This judge compares exactly**: values inside each quadruplet must be sorted ascending, and quadruplets must be in lexicographic ascending order.

## Constraints
- `1 <= nums.length <= 200`
- `-10^9 <= nums[i] <= 10^9`
- `-10^9 <= target <= 10^9`

## Examples
```text
Input: nums = [1,0,-1,0,-2,2], target = 0
Output: [[-2,-1,1,2],[-2,0,0,2],[-1,0,0,1]]
Explanation: The three unique quadruplets that sum to `0` are `[-2,-1,1,2]`, `[-2,0,0,2]`, and `[-1,0,0,1]`.
```

## Understanding & Intuition
The sorted array allows duplicate skipping and two-pointer pair search. Fixing two numbers reduces the problem to finding a two-sum target in the remaining suffix.

## Approach 1 — Naive / Brute Force
**Idea:** Try every quadruple and store sorted tuples to deduplicate.
```python
from typing import List

class Solution:
    def fourSum(self, nums: List[int], target: int) -> List[List[int]]:
        found = set()
        n = len(nums)
        for a in range(n):
            for b in range(a + 1, n):
                for c in range(b + 1, n):
                    for d in range(c + 1, n):
                        if nums[a] + nums[b] + nums[c] + nums[d] == target:
                            found.add(tuple(sorted((nums[a], nums[b], nums[c], nums[d]))))
        return [list(item) for item in sorted(found)]
```
- **Time:** O(n⁴) — **Space:** O(u)

## Approach 2 — Better
**Idea:** Precompute pair sums and combine disjoint pairs, deduplicating by values.
```python
from typing import List
from collections import defaultdict

class Solution:
    def fourSum(self, nums: List[int], target: int) -> List[List[int]]:
        pairs = defaultdict(list)
        n = len(nums)
        for i in range(n):
            for j in range(i + 1, n):
                pairs[nums[i] + nums[j]].append((i, j))
        found = set()
        for total, first_pairs in pairs.items():
            for i, j in first_pairs:
                for k, l in pairs.get(target - total, []):
                    if len({i, j, k, l}) == 4:
                        found.add(tuple(sorted((nums[i], nums[j], nums[k], nums[l]))))
        return [list(item) for item in sorted(found)]
```
- **Time:** O(n⁴) worst case, often less — **Space:** O(n²)

## Approach 3 — Optimal
**Idea:** Sort, fix the first two values, then use two pointers for the remaining pair.
```python
from typing import List

class Solution:
    def fourSum(self, nums: List[int], target: int) -> List[List[int]]:
        nums.sort()
        n = len(nums)
        result = []
        for i in range(n - 3):
            if i > 0 and nums[i] == nums[i - 1]:
                continue
            for j in range(i + 1, n - 2):
                if j > i + 1 and nums[j] == nums[j - 1]:
                    continue
                left, right = j + 1, n - 1
                while left < right:
                    total = nums[i] + nums[j] + nums[left] + nums[right]
                    if total == target:
                        result.append([nums[i], nums[j], nums[left], nums[right]])
                        left += 1
                        right -= 1
                        # Avoid returning the same quadruplet more than once.
                        while left < right and nums[left] == nums[left - 1]:
                            left += 1
                        while left < right and nums[right] == nums[right + 1]:
                            right -= 1
                    elif total < target:
                        left += 1
                    else:
                        right -= 1
        return result
```
- **Time:** O(n³) — **Space:** O(1) extra, excluding output

## Complexity Summary
| Approach | Time | Space |
|---|---|---|
| Naive | O(n⁴) | O(u) |
| Better | O(n⁴) worst | O(n²) |
| Optimal | O(n³) | O(1) extra |

## Edge Cases & Pitfalls
- Large positive and negative values require normal integer arithmetic; Python is safe.
- Skip duplicates at every fixed-pointer level.
- Pair-sum approaches must ensure all four indices are distinct.
